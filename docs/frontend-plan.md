# Vite 前端实施计划

日期: 2026-09-25.

状态: 前端功能已实现, 自动化验证与隔离 API 浏览器联调已完成. 真实 S3 与 VoxCPM2 推理验收待环境就绪后完成. 具体结果见第 9 节.

## 1. 目标与范围

为 ZVox 增加中文 Web 界面, 完成登录, 选择音色, 输入文本, 创建语音任务, 查看状态和播放结果的完整流程. 管理员通过独立页面管理用户, 导入 Speaker 和下载模型.

第一版复用现有 FastAPI 接口, 前端放在仓库根目录的 `frontend/`, 独立安装依赖和构建. 不调整后端业务逻辑和数据库结构.

本期不包含自助注册, 上传或编辑音色, 参考音频试听, 任务取消或删除, 批量生成, 实时流式播放和真实百分比进度. 当前接口未提供这些能力.

## 2. 现有实现与依据

| 来源 | 已确认的能力或约束 | 前端处理 |
| --- | --- | --- |
| [API 文档](api.md), [路由注册](../app/main.py) | 所有业务接口使用 `/api` 前缀, 已配置可选 CORS 来源 | 默认使用同源 `/api` |
| [认证接口](../app/api/users.py), [用户服务](../app/services/user.py) | Bearer Token 登录, 退出, 当前用户查询和改密; 无刷新 Token 接口 | 恢复会话时校验身份, 过期后重新登录 |
| [Speaker 接口](../app/api/speakers.py) | 列表与详情需登录后读取, 返回名称, 描述和头像 | 登录后浏览和选择音色, 不提供参考音频试听 |
| [任务接口](../app/api/jobs.py), [任务服务](../app/services/job.py) | 异步创建, 列表分页, 详情返回临时音频链接 | 提交后查询任务, 完成后播放 |
| [请求模型](../app/models/schemas.py) | 文本最多 4096 字符, 创建任务仅接收 `speaker_id` 和 `text` | 不增加语速, 音调等无对应接口的表单项 |
| [管理接口](../app/api/admin.py), [模型服务](../app/services/model.py) | `GET /admin/model` 可能触发下载; `/admin/model/status` 只查询状态 | 页面初始化只查状态, 用户点击按钮后才触发下载 |
| [任务查询](../app/db/database.py) | 普通用户只看自己的任务, 管理员可看全部; 分页只有时间游标 | 文案区分权限, 使用加载更多, 不展示总页数 |
| [URL 工具](../app/tools/url.py) | 音频使用预签名 URL, AWS 头像也可能过期 | 从 API 刷新链接, 不拼接存储地址 |

规划时仓库没有前端工程, `package.json`, `.nvmrc` 或 `.node-version`. 存在 `tests/test_regressions.py`, 后续若确需调整后端, 应执行相关回归验证.

规划时通过本地文件阅读和 `rg` 核对接口及调用关系. 当前未提供可调用的 augment-context-engine, LSP 和 Web Search MCP, 未执行这些工具的检查. 实现时通过浏览器直接查阅 Vite, React Router 和 Vitest 官方资料, 核实版本要求和配置方式.

## 3. 技术方案

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 构建工具 | Vite | 满足指定要求, 前端独立开发和产出静态文件 |
| 界面框架 | React + TypeScript | 作为未指定框架时的默认方案, 为 API 数据提供类型约束 |
| 路由 | React Router | 支持登录, 工作台, 任务详情和管理页面 |
| 样式 | 普通 CSS + CSS 变量 | 统一颜色, 间距和布局, 首期不引入完整 UI 组件库 |
| HTTP | 原生 `fetch` | 集中处理认证, JSON 和错误, 无需额外请求库 |
| 状态 | React 本地状态 + 会话 Context | 页面管理自己的数据, 只共享认证信息 |
| 音频 | 原生 `audio` 控件 | 提供播放, 暂停, 进度和音量控制 |
| 包管理 | pnpm | 遵循仓库约定, 提交 `pnpm-lock.yaml` |

开始实现时先查阅 Vite 官方资料, 确认所选版本的 Node.js 要求和配置方式. 再通过 nvm 安装和使用兼容版本, 写入 `frontend/.nvmrc`. 若届时仓库已有版本文件, 优先遵循现有配置; nvm 不可用时先询问用户, 不静默切换运行时.

仅抽取实际重复的 API 请求, 会话处理和轮询清理逻辑. 不引入通用表单引擎, 全局业务状态库或自动生成客户端.

## 4. 页面与交互

| 路由 | 权限 | 主要内容 |
| --- | --- | --- |
| `/login` | 公开 | 用户名和密码登录, 错误提示, 成功后返回站内目标页面 |
| `/` | 已登录 | 音色列表, 本地名称搜索, 选中音色, 文本编辑, 字数统计和生成入口 |
| `/jobs` | 已登录 | 任务状态, 文本摘要, 音色, 创建时间, 加载更多 |
| `/jobs/:id` | 已登录且任务可访问 | 完整文本, 状态, 错误原因, 音频播放和结果文件入口 |
| `/account` | 已登录 | 当前用户信息和修改密码 |
| `/admin/users` | 管理员 | 用户列表, 创建用户, 角色修改, 启用或停用, 密码重置 |
| `/admin/system` | 管理员 | Speaker 导入, 导入结果, 模型状态, 下载操作 |

只面向桌面浏览器, 不做移动端适配. 页面最小宽度 1024px, 更窄的窗口横向滚动. 使用侧栏导航, 工作台采用音色选择区和文本编辑区双栏布局. 初版采用浅色背景, 深色正文和单一强调色, 不引入主题切换.

所有页面提供加载中, 空数据和请求失败状态. 表单使用明确标签, 键盘可操作, 焦点可见; 状态通过文字和颜色共同表达. 头像缺失或加载失败时显示名称占位, 音色已撤下的历史任务仍展示原文本及音色 ID.

### 4.1 登录与权限

- 除 `/login` 外的页面都需要登录, 未登录时转到登录页, 登录后返回原页面. 登录页单独显示, 不含侧栏导航.
- Token 与 `expires_at` 存入 `sessionStorage`, 不持久保存密码. 刷新页面后通过 `GET /api/users/me` 恢复用户信息.
- 受保护接口统一添加 Bearer Header. 前端角色仅控制导航和页面访问, 权限以服务端响应为准.
- `401` 清理会话并转到登录页; 登录接口的 `401` 在表单内显示. `403` 显示无权限, 不进入反复登录跳转.
- 退出时调用 `POST /api/auth/logout`, 清理本地身份和用户数据, 停止轮询. 若服务端撤销失败, 明确提示结果, 不宣称 Token 已撤销.
- 修改密码成功后重新登录. 管理员修改自己的角色或状态后刷新身份, 避免继续显示失效的管理入口.

### 4.2 语音生成与任务

- 音色列表使用 `GET /api/speakers`, 名称搜索在已加载列表中完成. 没有可用音色时禁用生成, 并显示空状态.
- 文本为空白时禁止提交, 非空文本保留用户原始输入. 字数按 Unicode 码点计算, 与服务端 4096 字符限制对齐.
- 使用 `POST /api/jobs` 创建任务, 提交期间禁用按钮. 成功后跳转 `/jobs/{job_id}`, 失败时保留输入.
- 创建请求遇到网络中断时不自动重试, 提示先查看任务列表, 避免响应丢失后重复创建任务.
- 状态展示为 `pending` 排队中, `running` 生成中, `completed` 已完成, `failed` 失败. 不估算队列位置或完成百分比.
- 活跃任务详情约每 2 秒查询一次; 列表包含活跃任务时约每 5 秒更新已展示任务的状态. 刷新不丢弃已加载的历史页, 按 ID 合并数据.
- 前一次查询完成后再安排下一次. 页面隐藏时暂停定时查询, 恢复可见时刷新; 切换页面, 退出登录和终态任务均清理不再需要的轮询.
- 查询失败显示错误并退避重试, 上限 30 秒; `401`, `403`, `404` 停止对应查询, 不无限请求不可访问的任务.
- 列表每页请求 20 条, `before` 使用最后一条记录的原始 `created_at`, 正确编码查询参数. 返回不足 20 条时隐藏加载更多.
- 时间游标无法区分相同时间戳的记录, 这是当前接口限制. 前端去重不能修复遗漏, 本期不修改分页协议.

### 4.3 音频结果

- 仅在任务完成且存在 `result_url` 时显示播放器. 保留结果文件入口, 浏览器能否直接下载取决于存储响应头; 不承诺跨域 `download` 属性强制下载.
- 不持久缓存预签名 URL, 不给 S3 请求附加后端 Bearer Token. 重新打开详情或获取下载链接时重新查询任务详情.
- 播放错误时允许重新获取链接; 自动刷新最多一次, 再失败则显示可重试错误, 避免反复重载播放器.
- 部署联调确认浏览器可访问音频和头像地址, HTTPS 页面使用可访问的 HTTPS 资源. 本期不通过前端 `fetch` 转 Blob 下载, 避免额外的存储 CORS 依赖.

### 4.4 管理员功能

- 用户管理复用 `/api/admin/users` 及对应更新和密码接口. 校验用户名格式和 8-128 字符的新密码, 用服务端 `409` 说明重名或最后一位管理员保护.
- 停用, 降级和重置密码前显示操作对象与影响, 成功后刷新列表. 用户管理不提供删除入口.
- Speaker 导入前说明会更新索引并移除已从 S3 撤下的音色. 提交后轮询 `/api/admin/speakers/sync/status`, 兼容 `submitted` 和 `already_running`.
- 导入结果只展示 `imported`, `deleted`, `errors`, 不使用已弃用的上传或下载计数字段. 完成后刷新音色列表.
- 系统页面加载时请求 `/api/admin/model/status`. 仅点击检查并下载按钮时调用 `/api/admin/model`, 进行中禁用重复提交.
- 模型状态兼容 `{status: "ready", path}` 与 `{downloading, progress, path, error}` 两类响应. 只显示未就绪, 下载中, 已就绪或失败, 不把字符串 `progress` 当作百分比.

## 5. 目录与接口组织

计划新增:

```text
frontend/
  .nvmrc
  package.json
  pnpm-lock.yaml
  index.html
  vite.config.ts
  tsconfig*.json
  src/
    main.tsx
    App.tsx
    api/
      client.ts
      types.ts
      auth.ts
      speakers.ts
      jobs.ts
      admin.ts
    auth/
      AuthProvider.tsx
      RequireAuth.tsx
    components/
    pages/
    styles/
```

`api/client.ts` 只负责请求, Token, 取消请求和错误归一化; 处理 `204` 空响应, FastAPI 字符串或数组形式的 `detail`, 网络错误和非 JSON 响应. 页面负责表单和展示, 不直接拼接认证头.

类型以现有接口返回为依据, 区分任务列表和详情, 保留可空字段. `422` 映射字段校验, `404` 显示资源不可访问, `429` 提示稍后重试, `5xx` 显示服务异常. 不自动重试业务写入请求.

## 6. 开发与部署

- 开发时 Vite 将 `/api` 代理到本地 FastAPI 的 `http://127.0.0.1:8000`, 页面使用相对 API 地址. Python 和前端进程分别启动.
- 生产构建输出 `frontend/dist/`, 由静态服务器托管; 同一入口将 `/api` 转发到 FastAPI, 其余前端页面路径回退到 `index.html`. API 错误不能被 SPA 回退吞掉.
- 若实际部署要求前后端分域, 再增加公开的 API 基地址配置, 并通过现有 `CORS_ORIGINS` 允许指定前端来源.
- 前端配置仅包含公开连接信息, S3 密钥和模型路径配置继续留在后端. 后端仍按现有约束使用一个 Uvicorn Worker.
- 按需补充 README 的开发和构建命令, 更新 `.gitignore` 忽略依赖与构建产物. 当前 `.gitignore` 已有未提交修改, 后续编辑前阅读并保留这些改动.

## 7. 实施顺序与验收

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| 1. 工程基础 | 核实版本, nvm + pnpm 初始化, Vite 代理, 路由和样式基础 | 开发服务启动, 构建与类型检查通过, 可请求 Speaker 列表 |
| 2. 登录与工作台 | 会话恢复, 权限入口, 音色选择, 文本校验, 创建任务 | 登录后能创建任务并跳转详情, 错误不丢失输入 |
| 3. 任务与音频 | 历史分页, 状态轮询, 详情, 播放与链接刷新 | 完整走通生成流程, 页面切换后无遗留轮询 |
| 4. 账号与管理 | 改密, 用户管理, Speaker 导入, 模型状态和下载 | 普通用户无管理入口, 管理员操作结果清晰可见 |
| 5. 联调与交付 | 响应式检查, 异常路径验证, 部署说明 | 真实服务完成至少一次生成与播放, 构建产物可部署 |

每阶段只运行受影响范围内的最小有意义验证. 工程落地时提供 `typecheck`, `lint`, `test`, `build` 脚本, 使用 pnpm 执行. 自动化测试集中覆盖请求错误处理, 会话失效, 轮询终止和重复提交防护, 不为静态展示组件堆叠快照测试.

联调验收覆盖:

- 登录成功与失败, 刷新恢复会话, Token 过期, 退出和改密后重新登录.
- 空音色列表, 无头像, 空白文本, 4096 字符边界及非 BMP 字符计数.
- 任务排队, 运行, 成功和失败; `429` 限流; 普通用户访问他人任务返回 `404`.
- 历史加载更多, 进入旧任务详情, 链接过期后刷新, 播放或存储访问失败提示.
- 普通用户访问管理路由, 管理员重复导入, 导入错误, 模型未就绪及下载失败.
- 桌面布局, 键盘导航, 直接访问或刷新子路由, 生产 `/api` 代理.

真实 S3, 已发布的 Speaker, 可用模型和推理环境是最终端到端验收的前提. 若缺少这些环境, 应分别记录已完成的接口替身验证与尚未完成的真实生成验证.

## 8. 影响范围与修改前检查

- 复用范围: 已核对现有 API, 请求模型和服务逻辑, 没有现成前端可复用.
- 最简单方案: 单个 Vite SPA, 原生请求和音频能力, 页面局部状态, 不增加服务端渲染和额外后端服务.
- 必要范围: 实现阶段新增 `frontend/`, 更新 README 和本计划的实施记录. 构建与依赖忽略规则放在 `frontend/.gitignore`, 保留根 `.gitignore` 的既有改动.
- 风格一致性: 中文界面和文档, 英文标点, 小范围修改, 遵循 nvm 和 pnpm 约定.
- 变更清理: 删除临时文件, 未使用导入和调试日志. 如执行 Git 提交, 按仓库要求每个文件单独 `commit -m`, 使用 `<type>: <desc>` 格式.
